# CLASSFLOW AI

## Smart Classroom & AI Timetable Scheduler

---

# MASTER DEVELOPMENT PROMPT

You are a senior product architect, UI/UX designer, full-stack developer, AI engineer, database architect, and QA engineer.

Build a complete, production-quality web application called **ClassFlow AI — Smart Classroom & AI Timetable Scheduler**.

The application is designed for colleges and universities to automatically create optimized class timetables while managing faculty, classrooms, laboratories, subjects, divisions, availability, workload, and scheduling constraints.

The application must feel like a real SaaS product and not like a basic college CRUD project.

The UI should be modern, professional, responsive, clean, fast, and suitable for demonstrating at a hackathon.

---

# 1. PRODUCT VISION

ClassFlow AI solves the problem of manually creating college timetables.

Traditional timetable creation can cause:

- Faculty clashes
- Classroom conflicts
- Laboratory conflicts
- Uneven faculty workload
- Incorrect subject distribution
- Back-to-back lectures
- Underutilized classrooms
- Difficult timetable modifications
- Problems when a teacher or room becomes unavailable

ClassFlow AI should automatically generate an optimized timetable based on user-defined constraints.

The core concept is:

College Data
↓
Scheduling Constraints
↓
Optimization Engine
↓
Conflict Detection
↓
Optimized Timetable
↓
Admin Approval
↓
Faculty & Student Timetables

# 13. HARD CONSTRAINTS

These constraints MUST never be violated.

### Faculty conflict

A faculty member cannot teach two classes simultaneously.

### Room conflict

A room cannot be occupied by two classes simultaneously.

### Division conflict

A division cannot attend two subjects simultaneously.

### Faculty availability

A teacher cannot be scheduled when unavailable.

### Room capacity

Room capacity must be greater than or equal to class strength.

### Lab requirement

Subjects requiring laboratories must be assigned compatible laboratories.

### Required teaching hours

Every subject must receive its required number of weekly periods.

---

# 14. SOFT CONSTRAINTS

Try to optimize these.

- Avoid unnecessary free periods
- Avoid excessive consecutive lectures
- Avoid faculty overload
- Prefer faculty preferred slots
- Distribute subjects throughout the week
- Avoid too many difficult subjects consecutively
- Optimize classroom utilization
- Maintain reasonable breaks
- Prefer suitable rooms

The system should calculate an optimization score.

Example:

Timetable Score: 94/100

# 15. TIMETABLE OPTIMIZATION ENGINE

Use a constraint-based optimization approach.

Recommended technology:

Python
FastAPI
Google OR-Tools / constraint programming

The optimization engine should:

1. Receive scheduling data.
2. Generate possible time slots.
3. Apply hard constraints.
4. Generate feasible schedules.
5. Apply soft constraints.
6. Score schedules.
7. Select the best schedule.
8. Return the timetable to the Node.js backend.

Architecture:

React
↓
Node.js / Express
↓
Scheduling API
↓
Python FastAPI
↓
OR-Tools Optimization Engine
↓
Optimized Timetable
↓
MongoDB
